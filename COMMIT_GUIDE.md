📝 Git Commit & Tag Guide for Automated Wiki Releases

This guide explains how to write commits and create tags so that
Gitea Actions can automatically generate Docker images 🐳 and Wiki release pages 🤖.

🎯 Why this guide exists

Every Git tag creates:

A Docker image

A Wiki release page

Commit messages become human-readable changelogs

Developers don’t need to manually update the Wiki

📍 This file location:
COMMIT_GUIDE.md (repository root)
📍 Referenced from Wiki: Automated release pages link back to this file

1️⃣ Commit Message Format (Required)

Use the following structure:

<type>(<scope>): <short description>

(optional body)

✅ Allowed Types
Type	Purpose	Example
feat	New feature	feat(labs): add AI systems page
fix	Bug fix	fix(ui): correct navbar spacing
docs	Documentation	docs(readme): update setup steps
chore	Maintenance / tooling	chore(deps): update astro version
2️⃣ Breaking Changes 🚨 (Very Important)

If a change is not backward compatible, include BREAKING in the commit body:

feat(api): update lab config format

BREAKING CHANGE: lab.json schema has changed

What happens automatically?

⚠️ Wiki release will show “Breaking changes included!”

Developers immediately know to take caution

3️⃣ Git Tag Rules (Release Trigger)

Tags are what trigger the automation.

✅ Tag format
v<MAJOR>.<MINOR>.<PATCH>


Examples:

v1.0.0

v1.2.3

✅ Always use annotated tags
git tag -a v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0


🚀 This will:

Build & push Docker image

Generate Wiki release page

Update latest release pointer

4️⃣ What the Wiki Release Page Contains 🤖

Each release page is fully automated and includes:

Version number

Release date & UTC time

Person who triggered the release 🙂

Commit SHA

Breaking change warning (if detected)

Git comparison link to previous release

Docker image reference 🐳

⚠️ Do not edit these pages manually
They are regenerated by Gitea Actions.

5️⃣ Docker Image Naming 🐳

Docker images are published automatically to the Gitea registry:

git.k2labs.in/<owner>/<repo>:<tag>


Example:

git.k2labs.in/murkar/k2labs-website:v1.0.0

6️⃣ Typical Developer Flow 👩‍💻👨‍💻
# make changes
git add .
git commit -m "feat(labs): add healthcare intelligence lab"

# push code
git push origin main

# create release
git tag -a v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0


➡️ Everything else is handled by automation 🤖

7️⃣ FAQ
❓ I forgot to mark a breaking change

Add BREAKING in the commit body and create a new tag.

❓ Can I edit Wiki pages manually?

You can, but they may be overwritten.
Best practice: change commits → push tag.

❓ Who triggered the release?

Shown automatically in Wiki using Gitea actor metadata.

❓ Where is the automation defined?
.gitea/workflows/wiki-release.yml
